# Microduck 本地实验室

在本机运行 Pollen 官方机器人模型、ONNX 运动策略、Rust `robotd` 和 `robotctl`。物理层复用官方 CPU 验证脚本的 BAM M6 电机模型，用网页选场景、控制、保存世界轨迹并回放。所有数据留在本机。

## 启动

当前工作区已准备好依赖。在本目录运行：

```sh
python3 scripts/dev.py
```

打开 http://127.0.0.1:5173 。选择场景后开始，等待机器人站稳。按住 W 前进，A/D 向左/右前方转弯，S 停车，也可用页面按钮。松开移动按钮即停车，转弯会同时向前走。停止会保存记录，时间轴可回放；再次运行会启动新的官方进程和初始姿态。Ctrl+C 关闭服务。

首次在新机器准备依赖：

```sh
sh scripts/setup.sh
```

需要 Git、uv、Node.js 和 Rust 1.99+。运行只需 CPU；不安装训练用的 PyTorch、CUDA、mjlab 或 GStreamer。Python 运行依赖锁定在 `requirements.txt`，前端锁定在 `web/package-lock.json`。

## 接入自己的程序与官方 CLI

先在网页开始一个场景，再运行官方 CLI 包装入口：

```sh
.venv/bin/python scripts/robotctl.py health
.venv/bin/python scripts/robotctl.py monitor --json --hz 10
```

包装入口只发现当前会话的 socket，然后执行未经修改的官方二进制。控制服务是官方 Unix socket NDJSON JSON-RPC。程序示例：

```sh
.venv/bin/python examples/drive.py
```

示例通过 `robot.move` 连续发送五秒前进指令后停车；500ms 官方 deadman 保留。`GET /api/status` 提供本次 socket，可由自己的程序直接连接。CLI 是已接入的官方接口；Python SDK 尚未做完整兼容验收。

网页基准动作使用前进 `vx=0.3`、转弯 `vx=0.3, vyaw=±0.5`。API 和官方 socket 原样传递用户速度，不做隐式放大；基准策略在较低速度或原地转向时可能保持站立。

## 场景和结果

提供 21 个场景：8 个简单场景、8 个进阶场景、5 个复杂场景。页面按难度筛选并显示分类数量，卡片区分基础移动和障碍导航。难度依据布局、空间限制及转弯要求划分，尚不是模型通过率的统计评级。实时模式需要手动或自己的程序控制；快速试跑使用内置参考导航程序。目标圈是评测标记，非物理障碍。

平地场景距离以机器人站稳时的位置和朝向为基准；障碍场景的箱体、路线和目标固定在世界坐标中。记录保存起始姿态和最终世界目标，显示、评分与回放使用同一坐标。

评分使用 MuJoCo 世界根位置，不使用机器人里程计估计。完成度 0–100 表示历史最佳距离改善；成功要求在结束前最后连续 0.5 秒停留在半径 0.18m 的目标区域，且全程无跌倒或环境碰撞。跌倒暂按躯干重力方向判定（gravity z > -0.4），碰撞不统计正常地面接触。箱体场景记录机器人与箱体的真实接触；撞到障碍即不满足成功条件。

`data/runs/*.json` 保存位置、根姿态、15 关节、仿真/实际时间、障碍物布局、场景快照、难度分类、评分及版本。`data/logs/` 保存官方进程日志。网页机器人是简化外观，用真实位置、根姿态和腿关节展示，尚未逐部件精确复原官方 CAD。未实现摄像头、可靠垃圾抓取搬运、视频导出或上传程序执行。

每次运行另保存 `diagnostics`：网页控制指令的发送时间、往返耗时、接受结果，以及定期读取的官方 `robot.health`。网页显示实测控制频率、指令数量和延迟，历史回放也可查看。直接通过官方 CLI 或外部程序发送的指令不经过网页接口，因此不计入网页指令列表；其实际运动仍会记录。诊断采样失败不影响物理记录，也不改变评分。

官方控制服务采用真实时间。运行期间网页失焦会停止网页移动指令，网络中断仍由官方 deadman 停车。仿真异常退出标记失败，保留已收到的轨迹，绝不生成替代运动数据。

启动后须连续站稳才开始计分。默认采用已做原生验证的 alpha walking/stand 与 BAM M6 配对，实测控制频率可从页面诊断查看。模型和硬件差异仍需校准；当前评分用于本地场景对比，不能直接推断真实机器人表现。

## 快速试跑与正常速度回放

选择任一场景，点击「快速试跑」。内置参考导航程序直接运行官方 alpha ONNX 与 BAM MuJoCo，每次控制推理对应 4 个 5ms 物理步，不等待真实时间；到达并停稳后自动保存。页面分别显示仿真时长和计算耗时。冷启动和机器性能影响实际耗时，速度不固定。回放按轨迹的仿真时间默认以 1× 播放，可选择 0.5×、2×、4×、8×，与计算耗时无关。

此模式记录为 `fast_reference` / `offline-alpha-bam-v1`，从官方 STAND2 姿态启动，动作比例采用官方 CPU 验证脚本的 1.0。实时模式从坐姿站起、通过官方 robotd 控制，动作比例为 0.9；两者是不同执行配置，比较评分时应保持模式一致。快速模式不是原生 CLI 的倍速运行，自己的 CLI／SDK 程序仍使用「开始运行」。

接口：`POST /api/runs` 使用 `{"scenario_id": "straight", "mode": "fast_reference"}`；省略 mode 保持实时运行。快速模式禁用手动控制，可停止并保存已计算的轨迹。

## Roadmap

按以下顺序扩展本地平台；未标为完成的条目尚未实现。

| 阶段 | 内容 | 验收条件 |
|---|---|---|
| 已完成 | 平地移动、快速参考试跑、评分和正常速度回放 | 同一轨迹显示与评分一致，保存后可重复播放 |
| 已完成 | 场景分类、真实障碍物、走廊、停靠、连续门与绕行场景 | 障碍参与 MuJoCo 碰撞；回放还原布局；到达且无碰撞才成功 |
| 已完成 | 左右脚踢球，通过球门线判定射门 | 复用官方 kick_left/kick_right；记录球的位置、运动方向与射门结果 |
| 实验性实现 | 物品从 A 点拾起、搬运至 B 点并放下 | 官方拾取与行走策略配合接触触发的模拟夹持；以物体真实抬升、搬运、释放和落稳分阶段评分 |
| 后续 | LLM 接入：状态观测和受限动作工具 | 模型读取位置、朝向、目标和障碍；调用移动、停车、技能；每个决策周期同步推进模拟时间 |
| 后续 | 多模态观测 | 机器人视角图像、遮挡和视野；区分完整世界状态评测与仅视觉评测 |
| 后续 | 程序／模型评测 | 标准观测与动作协议、固定种子、配置版本；比较成功率、碰撞、调用次数、延迟和费用 |

LLM 负责理解任务与决策，现有运动策略负责关节动作和平衡。模型请求期间暂停仿真时钟，收到动作后推进固定时长；分别记录模拟耗时和模型响应耗时。后续 CLI 加速也需要遵守模拟时钟协议，不能简单加快身体而保留墙钟控制。

[Pollen 官方产品页](https://pollen-robotics.com/microduck/)列出 Kick 和 Grab；Grab 的描述是低头到地面、舀取后站直。当前本地已下载相应动作策略，但播放一次拾取动作不等于已完成任意物体抓取。踢球的物体物理、任务评分和回放现已接入；拾取现提供 A → B 搬运实验，使用尚未按硬件校准的模拟夹持；不能把它当作真实嘴部抓取能力的验证。

障碍场景的快速试跑由参考导航程序沿预设绕行点行走；这用于验证场景和物理，不代表模型自主发现路线。自己的程序在实时模式下自行规划路线。旧记录没有障碍布局时按无障碍记录回放。

场景筛选不改变任务的目标和物理参数。运行期间不能切换分类或场景；打开历史记录时同步选择对应场景。新的记录保存 `difficulty`、`category` 和完整 `scenario_snapshot`，旧记录仍可回放。

难度分组：简单为原有 8 个平地移动任务；进阶为左右绕障、直线走廊、箱间停靠、连续双门、缓坡上下坡与左右脚射门；复杂为交错障碍通道、长岛绕行、斜置长障碍、偏置双门及实验性拾取。每个障碍任务仍使用真实 MuJoCo 接触与同一成功标准。

真正的坡道场景是「缓坡上下坡」：两个三角棱柱形成 4.3° 的上下坡，最高 6cm；显示与 MuJoCo 碰撞几何使用相同顶点。坡面是可行走地形，正常脚部接触不算撞障碍；跌倒仍按相同规则判定。「斜置长障碍」仅指平地上斜放的箱体。记录保存 `terrain`，历史回放还原坡面。

回放速度依据仿真时间推进，以浏览器单调时钟计算当前时刻；高倍速可跳过显示中间帧，完整记录不删减。暂停和拖动时间轴保持可用，回放倍速不影响物理计算或评分。

## 踢球和实验性拾取

进阶场景提供「左脚射门」「右脚射门」。选择后点击快速试跑，直接执行官方 ball_kick_left/right 策略。球使用官方 70mm、15g 仿真模型；比赛目标是宽 1m、x=0.4m 的球门线。门柱用于显示，不是碰撞实体。球在记录开始前摆放一次，随后全部运动来自真实接触，运行期间不重新摆球。成功要求球先与机器人实际接触，再穿过球门线，且没有跌倒。记录保存球位置与完整轨迹，支持各档回放速度。

复杂场景「物品搬运 A → B」把初始垃圾位置标为 A，将 x=0.6m 的放置目标标为 B。垃圾是 5g、20×25×20mm 的自由刚体，记录实际位置、旋转和接触。官方 alpha_ground_pick 与行走策略负责低头、起身及移动；实验性 `simulated-contact-gripper-v1` 在物体接触后使用弹簧力夹持物体，搬运至 B 后解除夹持，再等待物体落稳。记录开始后不直接改写物体位置。

评分分为 `picked_up`、`transported`、`placed` 三阶段，只有真实抬升、搬运到 B、释放并落稳全部成立才算完成。仅低头、触碰或推到目标不会判定成功；中途停止保留实际阶段。页面与回放显示 A/B 标记、动作阶段、夹持/松开状态、实际抬升和三个阶段的结果。

官方 XML 没有已验证的嘴部活动关节与夹持碰撞面。本实验的模拟夹持明确是平台扩展，尚未按硬件校准，不能把它等同于真实机器人的嘴部抓取保真验证。后续需要根据嘴部结构校准夹持关节、接触和抓取能力。旧的拾取练习失败记录仍能回放。

这三个技能场景目前仅支持快速试跑，实时启动会拒绝；原导航场景实时 CLI 能力保持。接口 `/api/skill` 在实时运行时按白名单转发官方 `robot.do`，参数 name 只允许 kick_left、kick_right、ground_pick；它不替代动态物体场景的实时接入。

## 界面语言

页面右上角可切换简体中文、English、日本語和한국어。场景名称、操作、回放、评分与诊断随语言切换；选择保存在当前浏览器。切换语言不会重启仿真或更改录制数据。尚未收录的外部程序错误会保留原文。
